# RADIO2 — second radio preset for the repeater filter fork

Status: **implemented**. This document is both the implementation contract and
the user manual; the code lives in `examples/simple_repeater/Radio2*` and the
core enabler is behaviour-neutral when radio2 is off. Native coverage is the
`native_radio2` / `native_radio2_san` suites.

Scope: `examples/simple_repeater/` only. The core changes are generic and
behaviour-neutral when radio2 is off. No companion/room/sensor role gets the
feature.

---

## 1. Summary

Add a second LoRa preset to the repeater. One transceiver time-shares between
the primary preset (`radio`) and the secondary preset (`radio2`).

The feature must:

- keep the primary profile protected;
- treat the secondary profile as a bonus;
- work with `powersaving` enabled (MCU light sleep), because solar repeaters
  need it;
- allow the operator to choose how a packet heard on one profile is handled;
- cross profiles only for **broadcast flood** traffic;
- keep direct, ACK, path-return and unicast-flood DM traffic on the profile it
  was heard on;
- send replies on the profile the request arrived on;
- apply the existing packet filter to both profiles equally in v1;
- use its own persisted config file;
- keep the upstream diff small and generic.

RXPS (`radio.rxps`) and radio2 are mutually exclusive. `powersaving` and radio2
are compatible and required.

---

## 2. Non-goals

Do not implement in v1:

- cross-profile direct messages, ACKs, path returns, traces, anonymous requests,
  or unicast flood DMs;
- a bridge flow table / ACK matching / return-path state;
- foreign protocols (Meshtext, Ethernet, KISS, media);
- temporary radio2 leases (`tempradio2`);
- on-chip LR2021 multi-SF scanning;
- per-profile noise floors;
- per-profile filter rules (phase 2 only);
- simultaneous RX on two presets (impossible on one transceiver);
- partial packet transmission (never possible; TX is atomic).

## 3. Terms

| Term | Meaning |
|---|---|
| primary | The existing `radio` preset, stored in `/com_prefs`. |
| secondary | The new `radio2` preset, stored in `/radio2_cfg`. |
| profile | A frequency/bandwidth/SF/CR tuple. |
| broadcast flood | A flood packet with no unicast destination: advert, group text, group data. |
| unicast flood | A DM/request/response sent with flood routing. It is **not** crossable. |
| active mode | Primary has been heard recently; primary gets priority. |
| idle mode | Primary has been quiet long enough; secondary gets the maximum safe share. |
| visit | A contiguous period listening on one profile. |
| hold | In idle mode, finishing a secondary packet that is already in progress at the visit deadline. |
| abort | In active mode, retuning away from an in-progress secondary receive; the packet is dropped, never transmitted partially. |

## 4. User-visible behaviour

### 4.1 Defaults

- radio2 is **off**.
- policy: `primary=same`, `secondary=same` (isolated two-network repeater).
- advert: `primary`.
- replies: always the origin profile.
- filters: apply to both profiles equally.
- RXPS: must be off while radio2 is enabled.
- powersaving: may be on; radio2 uses it.

### 4.2 Policy matrix

Each origin has one action:

| Action | Meaning |
|---|---|
| `same` | Repeat only on the profile it was heard on. |
| `other` | Repeat only on the other profile. |
| `both` | Transmit two copies, one on each profile. |
| `drop` | Do not repeat; still process locally. |

The complete matrix:

| Heard on | `same` | `other` | `both` | `drop` |
|---|---|---|---|---|
| primary | TX primary | TX secondary | TX both | no TX |
| secondary | TX secondary | TX primary | TX both | no TX |

`both` is two sequential transmissions, not simultaneous. It consumes two
packet-pool slots while queued, two airtime charges, and shares the same
duty-cycle budget.

### 4.3 Packet classes

Cross-profile actions (`other`, `both`) apply only to **broadcast flood**:

- `PAYLOAD_TYPE_ADVERT` (adverts, including zero-hop adverts)
- `PAYLOAD_TYPE_GRP_TXT` when `isRouteFlood()`
- `PAYLOAD_TYPE_GRP_DATA` when `isRouteFlood()`

Everything else is **not crossable**:

- direct/transport-direct packets
- ACKs
- path returns
- traces
- anonymous requests
- unicast flood DMs (`REQ`, `RESPONSE`, `TXT_MSG`, `PATH`, `ANON_REQ`, etc.)
- control packets
- raw custom packets

For a non-crossable packet, the effective action is:

- `drop` if the configured action is `drop`;
- otherwise `same`.

This is the rule that avoids the flooded-DM ACK/path trap. A unicast flood DM
stays on its origin profile; its ACK/path return therefore also stays there.

### 4.4 Replies

Replies to a received packet are always sent on the profile the request arrived
on. This includes:

- CLI replies
- ACKs generated by the core
- path returns
- control/discover responses
- fleet acknowledgements

There is no `radio2.reply` setting. Origin is the rule.

Locally originated, non-reply traffic:

- adverts: `radio2 advert primary|both` (default `primary`)
- battery/fleet alerts: primary
- scheduled fleet scripts: primary unless the script is a reply to a received
  fleet message, in which case the captured origin profile is used

### 4.5 Adverts

`radio2 advert primary` (default): local adverts go on primary only.

`radio2 advert both`: local adverts are transmitted once on each profile.

Received adverts follow the policy matrix (they are broadcast flood).

### 4.6 Filters

v1: the existing filter applies to both profiles equally. A packet heard on
either profile goes through the same rule list.

Phase 2: add a per-rule `radio=any|primary|secondary` predicate. Default `any`.
See §14.

### 4.7 RXPS and powersaving

- `radio.rxps` and radio2 are mutually exclusive.
- `set radio2 ...` refuses while RXPS is enabled.
- `set radio.rxps on/...` refuses while radio2 is enabled.
- `set radio.rxps off` is always allowed.
- If both are somehow persisted, radio2 does not start; primary RXPS continues;
  `radio2` status reports the conflict.
- `powersaving` is allowed and required on nRF52 and ESP32. radio2 provides a
  timed wake deadline so the MCU can sleep between visits: ESP32 uses light
  sleep with a timer expiry; nRF52 uses an RTC2 one-shot (with a `delay()`
  fallback on a part that has no RTC2).
- Other board families have no sub-second timed wake: they do not override
  `sleep()`, so the default `sleepMs()` also does nothing. radio2 stays correct
  there — the main loop polls between visits — but `powersaving` saves no
  power. Use nRF52 or ESP32 when the repeater is solar/battery powered.

### 4.8 Noise floor

There is one shared noise floor, as today. No per-profile floor. `radio2`
status may show the current value. If `int.thresh` is enabled, the value is a
blend while scanning; this is accepted.

### 4.9 Isolation when off

radio2 is off by default. Once it is off and settled (`enabled=0`, no pending
apply, already back on primary), the feature is inert:

- no profile controller is installed on the radio: `selectTxProfile()` is the
  core's default no-op;
- `radio2.loop()` is not called (`needsService()` is false) — no retunes, no
  timers, no lazy-save passes;
- `logRx`/`logTx` and the receive policy hook are skipped; receive, forwarding,
  battery, filter, fleet and observer code take their original paths;
- `getSleepMs()` returns 0, so `main.cpp` takes exactly the same sleep/no-sleep
  branch it took before the feature existed;
- no packet is duplicated and `radio2 advert both` is inert;
- `/radio2_cfg` is read only at boot (two `exists` checks plus a 22-byte read
  when present) and written only after a radio2 CLI change.

The residual cost while off is boolean checks, not actions: one
`needsService()` per main loop, one `isScanning()` per packet, one
profile-control pointer check per transmit attempt, and two local metadata bytes
per packet. No RF activity, no timer, no wakeup, no extra filesystem write.

The only window that is not fully "off" is the deliberate deferred apply after
`radio2 off` (up to `RADIO2_APPLY_DELAY_MS`, then until a packet in progress
finishes): the radio may still be on the secondary preset for that moment and
is retuned back to primary before the scanner stops.

## 5. Architecture

Two layers:

1. **Generic core enabler** (small upstream diff):
   - one local-only profile byte on `mesh::Packet`;
   - `PacketManager::peekNextOutbound()`;
   - `Radio::selectTxProfile()`;
   - `Dispatcher` selects the TX profile before airtime/CAD;
   - `Dispatcher::default_tx_profile` for reply routing;
   - `MainBoard::sleepMs()` for timed wake.

2. **Fork-owned radio2 feature**:
   - config, persistence, CLI, policy, scheduler, status;
   - a `Radio2Device` interface so the policy/scheduler is host-testable;
   - a `RadioProfileControl` implementation the radio wrapper calls.

The core never knows what “radio2” means. It only knows a packet has a target
profile 0/1 and a radio can select it.

## 6. Core changes

### 6.1 `src/Packet.h` — one local profile byte

`Packet` is currently 260 bytes. The last field `_snr` is at offset 258; there
is one byte of tail padding at offset 259. Add one byte there. `sizeof(Packet)`
must stay 260.

Add after `_snr`:

```cpp
  // Local-only routing metadata. Never written on air, never hashed.
  // bits 0-1: TX target profile (0 primary, 1 secondary)
  // bits 2-3: RX origin profile (0 primary, 1 secondary, 3 unknown/local)
  uint8_t radio_profiles = 0;

  uint8_t getTxProfile() const { return radio_profiles & 0x03; }
  void setTxProfile(uint8_t p) {
    radio_profiles = (uint8_t)((radio_profiles & ~0x03) | (p & 0x03));
  }
  uint8_t getRxProfile() const { return (radio_profiles >> 2) & 0x03; }
  void setRxProfile(uint8_t p) {
    radio_profiles = (uint8_t)((radio_profiles & ~0x0C) | ((p & 0x03) << 2));
  }
```

Add constants near the top of `Packet.h` or in `MeshCore.h`:

```cpp
#define RADIO_PROFILE_PRIMARY    0
#define RADIO_PROFILE_SECONDARY  1
#define RADIO_PROFILE_UNKNOWN    3
```

Add after the class:


Do **not** add the byte to `writeTo()`/`readFrom()`. It is local metadata.

`Packet::Packet()` does not need an explicit assignment because the NSDMI

### 6.3 `src/Dispatcher.cpp` — select before airtime/CAD

Current `checkSend()` checks the channel before it pops the packet. Change it
to peek first, select the profile, then do the budget/CAD checks, then pop.

At the top of `checkSend()`:

```cpp
void Dispatcher::checkSend() {
  const uint32_t now = _ms->getMillis();
  if (_mgr->getOutboundCount(now) == 0) return;

  Packet* next = _mgr->peekNextOutbound(now);
  if (!next) return;

  if (!_radio->selectTxProfile(next->getTxProfile())) return;

  updateTxBudget();

  uint32_t est_airtime = _radio->getEstAirtimeFor(MAX_TRANS_UNIT);
  // ... existing budget check ...
  if (!millisHasNowPassed(next_tx_time)) return;
  // ... existing isReceiving()/CAD check ...
  cad_busy_start = 0;

  outbound = _mgr->getNextOutbound(now);
  // ... existing send path ...
}
```

Notes:

- `selectTxProfile()` must run before `getEstAirtimeFor()` and before
  `isReceiving()`/CAD, so the estimate and channel check use the TX profile.
- If `selectTxProfile()` returns false, return and retry next loop. The packet
  stays queued.
- `peekNextOutbound()` and `getNextOutbound()` must select the same packet.

### 6.6 `src/helpers/radiolib/RadioLibWrappers.h/.cpp` — retune and control

Add to `RadioLibWrapper`:

```cpp
  RadioProfileControl* _profile_control = nullptr;

public:
  void setProfileControl(RadioProfileControl* control) { _profile_control = control; }

  bool selectTxProfile(uint8_t profile) override {
    return _profile_control ? _profile_control->selectTxProfile(profile) : true;
  }

  // True when a complete packet is waiting to be read by recvRaw().
  // Declared here, defined in RadioLibWrappers.cpp: `state` is file-static.
  bool hasCompletedReceive() const;

  // True while a preamble/header/payload is being received.
  bool isReceiveInProgress();

  // Stop RX, apply a new preset, restart continuous RX. Returns false if a
  // complete packet is pending, if a receive is in progress and
  // `abort_receive` is false, or if the radio rejects the change.
  // `abort_receive=true` is used only by the scheduler's active-mode
  // secondary deadline: it abandons an in-progress secondary receive.
  bool retune(float freq, float bw, uint8_t sf, uint8_t cr,
              bool abort_receive = false);
```

Implementation in `RadioLibWrappers.cpp`:

```cpp
bool RadioLibWrapper::hasCompletedReceive() const {
  return (state & STATE_INT_READY) != 0;
}

bool RadioLibWrapper::isReceiveInProgress() {
  return isReceivingPacket();
}

bool RadioLibWrapper::retune(float freq, float bw, uint8_t sf, uint8_t cr,
                             bool abort_receive) {
  if (hasCompletedReceive()) return false;
  if (!abort_receive && isReceiveInProgress()) return false;
  idle();                 // stops RXPS if armed, standby, state = IDLE
  setParams(freq, bw, sf, cr);
  int16_t err = startReceiveMode();
  if (err != RADIOLIB_ERR_NONE) return false;
  state = STATE_RX;
  return true;
}
```

`idle()` and `startReceiveMode()` are protected members of the base, so this
method belongs in the base. `setParams()` is the existing virtual implemented by
every family wrapper. `state` is the file-static ISR flag in
`RadioLibWrappers.cpp`, which is why the two predicates are defined there rather
than inline in the header.

Do not call `retune()` while `_rx_ps_enabled` is true. Radio2 refuses to start
with RXPS on; if that invariant is ever broken, `retune()` should return false
rather than silently re-arm RXPS.

Refactor the existing `sleep(uint32_t secs)` into a common microsecond helper:

```cpp
  void sleepUs(uint64_t us) {
    if (inhibit_sleep) { delay(1); return; }
    gpio_num_t wakeupPin = (gpio_num_t)getIRQGpio();
    if (us > 0) esp_sleep_enable_timer_wakeup(us);
    portENTER_CRITICAL(&sleepMux);
    if (gpio_get_level(wakeupPin) == HIGH) {
      portEXIT_CRITICAL(&sleepMux);
      delay(1);
      return;
    }
    esp_sleep_enable_gpio_wakeup();
    gpio_wakeup_enable(wakeupPin, GPIO_INTR_HIGH_LEVEL);
    esp_light_sleep_start();
    gpio_wakeup_disable(wakeupPin);
    gpio_set_intr_type(wakeupPin, GPIO_INTR_POSEDGE);
    portEXIT_CRITICAL(&sleepMux);
  }

  void sleep(uint32_t secs) override { sleepUs((uint64_t)secs * 1000000ULL); }
  void sleepMs(uint32_t ms) override { sleepUs((uint64_t)ms * 1000ULL); }
```

Preserve `inhibit_sleep`, the DIO check, the critical section and the GPIO

### 6.9 `src/helpers/NRF52Board.cpp/.h` — timed wake

`NRF52Board::sleep()` currently ignores `secs` and wakes on any interrupt. Add
`sleepMs(uint32_t ms)` that arms a one-shot low-power timer for `ms`, then uses
the existing `sd_app_evt_wait()` / `__WFE()` path.

Implementation:

- Use RTC2 (`NRF_RTC2`, prescaler 0, compare channel 0) as the one-shot
  low-power deadline. RTC0 belongs to the SoftDevice and RTC1 is not disturbed,
  so `millis()`/FreeRTOS and Bluefruit are unaffected.
- A small `RTC2_IRQHandler` only sets a flag; the sleep loop clears the compare
  event after waking. The loop re-enters `sd_app_evt_wait()` / `__WFE()` on
  spurious wakeups and exits only on the timer, so radio DIO and SoftDevice
  events still wake it immediately.
- If the part has no RTC2, fall back to `delay(ms)` (correct but not low power)
  and log a debug message. Do not silently sleep without a deadline.
- Keep the existing FPU errata workaround.

This is the highest-risk platform piece. Validate on `RAK_4631_repeater` and
at least one other nRF52 target.

### 8.2 Crossable classification

```cpp
static bool radio2Crossable(const mesh::Packet* pkt) {
  switch (pkt->getPayloadType()) {
    case PAYLOAD_TYPE_ADVERT:
      return true;
    case PAYLOAD_TYPE_GRP_TXT:
    case PAYLOAD_TYPE_GRP_DATA:
      return pkt->isRouteFlood();
    default:
      return false;
  }
}
```

### 8.3 Effective action

```cpp
Radio2Action Radio2::actionFor(uint8_t origin, const mesh::Packet* pkt) const {
  Radio2Action configured = origin == RADIO_PROFILE_PRIMARY
      ? policy_primary : policy_secondary;
  if (!radio2Crossable(pkt) && configured != RADIO2_ACTION_DROP) {
    return RADIO2_ACTION_SAME;
  }
  return configured;
}
```

### 8.4 Target profile

```cpp
uint8_t Radio2::targetFor(Radio2Action action, uint8_t origin) const {
  switch (action) {
    case RADIO2_ACTION_SAME:  return origin;
    case RADIO2_ACTION_OTHER: return origin ^ 1;
    case RADIO2_ACTION_BOTH:  return origin;   // copy gets origin ^ 1
    case RADIO2_ACTION_DROP:  return origin;   // unused
  }
  return origin;
}
```

Helpers:

```cpp
static bool radio2IsRetransmit(mesh::DispatcherAction action) {
  return action != ACTION_RELEASE && action != ACTION_MANUAL_HOLD;
}

void MyMesh::radio2QueueDuplicate(mesh::Packet* pkt, mesh::DispatcherAction action,
                                  uint8_t origin) {
  uint8_t priority = (uint8_t)((action >> 24) - 1);
  uint32_t delay = action & 0xFFFFFF;
  mesh::Packet* copy = obtainNewPacket();
  if (!copy) { radio2.noteBothDrop(); return; }
  *copy = *pkt;
  copy->setTxProfile(origin ^ 1);
  sendPacket(copy, priority, delay);
  radio2.noteBoth();
}
```

`sendPacket()` validates and queues. The original is queued by
`Dispatcher::processRecvPacket()` after `onRecvPacket()` returns.

### 8.6 `MyMesh::allowPacketForward`

At the very top:

```cpp
bool MyMesh::allowPacketForward(const mesh::Packet* packet) {

```

Rationale: a policy `drop` is a deliberate routing decision, not a battery or

see non-group packets that the policy drops. Document this in `RADIO2.md`.

## 9. Scheduler

### 9.1 Goals

- Primary is the home profile.
- Primary traffic always wins.
- When primary is active, secondary gets a small share and may lose packets.
- When primary is idle, secondary gets the maximum share that still keeps
  primary capture bounded.
- In idle mode, a secondary packet already in progress may finish.
- In active mode, a secondary packet in progress at the deadline is aborted
  (RX abandoned; no partial TX).
- TX is never aborted; the scanner waits for it.

### 9.2 Constants

Put in `Radio2Config.h`:

```cpp
#define RADIO2_ACTIVE_HOLD_MS        30000UL  // primary active for 30 s after a packet
#define RADIO2_SWITCH_US             3000UL   // one retune, conservative default
#define RADIO2_LOOP_MARGIN_US        2000UL   // main-loop jitter allowance
#define RADIO2_MIN_VISIT_US          5000UL   // avoid absurdly short visits
#define RADIO2_ACTIVE_SECONDARY_DIV  4U       // active: primary visit = 4x secondary
#define RADIO2_HOLD_POLL_MS          5UL      // idle hold re-check interval
#define RADIO2_SLEEP_MAX_MS          1000UL   // cap one board sleep
#define RADIO2_APPLY_DELAY_MS        2000UL   // deferred RF apply after CLI
#define RADIO2_MAX_SWITCH_FAILURES   10U
#define RADIO2_SWITCH_RETRY_MS       1000UL
#define RADIO2_OVERLAP_GUARD_KHZ     6.0f
```

`RADIO2_SWITCH_US` should be measured on hardware. A boot self-test is optional;
if implemented, use the measured maximum plus 10%, and report it in
`radio2 timing`. Until measured, 3000 us is the conservative default.

### 9.3 Profile timing

For a profile:

```text
symbol_us = 2^SF * 1000 / BW_kHz
preamble_symbols = (SF <= 8) ? 32 : 16
capture_us = capture_symbols * symbol_us
bound_us = (preamble_symbols - capture_symbols) * symbol_us
           - 2 * switch_us - loop_margin_us
```

`capture_symbols` comes from
`radio_driver.rxPowerSavingCaptureCostSymbols()` (6 on SX126x, 8 on LR11x0).
`preamble_symbols` mirrors `RadioLibWrapper::preambleLengthForSF()`.

Definitions:

- `primary_capture_us` = minimum primary visit to latch a primary preamble.
- `secondary_capture_us` = minimum secondary visit to latch a secondary preamble.
- `primary_bound_us` = maximum secondary visit that still lets a primary
  preamble survive to the next primary visit.
- `secondary_bound_us` = maximum primary visit that still lets a secondary
  preamble survive to the next secondary visit.

Validation:

```text
secondary_capture_us <= primary_bound_us
primary_capture_us   <= secondary_bound_us
```

If either fails, the preset pair cannot be scanned without risking primary.
Reject radio2 with a clear error and keep primary unchanged.

Use `int64_t` for the multiplications; clamp to `uint32_t`.

### 9.4 Active mode

Trigger: `now - last_primary_packet_ms < RADIO2_ACTIVE_HOLD_MS`.

```text
secondary_visit = max(secondary_capture_us, RADIO2_MIN_VISIT_US)
primary_visit   = max(primary_capture_us,
                      RADIO2_ACTIVE_SECONDARY_DIV * secondary_visit)
```

If `primary_visit > secondary_bound_us`, secondary preambles will not survive
the primary visit. That is accepted in active mode: secondary only catches
packets that start during its visit. Mark `secondary_lossy = true` for status.

Primary is protected: the secondary visit is at most `primary_bound_us` by
validation, and a primary packet in progress defers the visit.

### 9.5 Idle mode

Trigger: `now - last_primary_packet_ms >= RADIO2_ACTIVE_HOLD_MS`.

```text
primary_visit   = max(primary_capture_us, RADIO2_MIN_VISIT_US)
secondary_visit = primary_bound_us
```

This gives secondary the maximum safe share. Both capture bounds hold by
validation. For symmetric presets this is roughly 62% secondary / 38% primary;
for asymmetric presets it follows the bounds.

If `secondary_visit < secondary_capture_us`, validation would have failed.

### 9.6 State machine

State:

```cpp
enum Phase { PHASE_PRIMARY, PHASE_SECONDARY };
Phase phase = PHASE_PRIMARY;
uint8_t current = RADIO_PROFILE_PRIMARY;
uint32_t phase_end_ms = 0;
uint32_t last_primary_packet_ms = 0;
bool paused = false;
bool pending_apply = false;
uint32_t pending_apply_at_ms = 0;
```

`begin()` sets `last_primary_packet_ms = millis()` so the node starts in active
mode for the first 30 s.

`loop(fs, quiet)`:

1. If (disabled or paused) and `!pending_apply`: if current != primary,
   `switchTo(PRIMARY, false)`; return. (A complete packet is never abandoned;
   the switch retries next loop.) `pending_apply` is excluded so a deferred
   `radio2 off` still lets the command reply go out on the old secondary
   config before the radio moves.
2. If `pending_apply` and `!paused` and `quiet` and `now >= pending_apply_at_ms`:
   apply the saved config. If the current profile is secondary and the new
   config is still enabled, retune it with `switchTo(SECONDARY, false, true)`
   (force, because the profile number did not change but the RF tuple did). If
   the new config is disabled and the current profile is secondary, switch to
   primary. If the required retune succeeds, clear pending, set `phase` to
   match `current`, and set `phase_end_ms` to the current mode's visit for that
   profile; otherwise keep pending and retry. Return.
3. If `!device.isInRecvMode()`: return (TX or idle; wait for RX).
4. If `device.hasCompletedReceive()`: return (let core read it).
5. If `now < phase_end_ms`: return.
6. Compute mode and visits from `last_primary_packet_ms`.
7. If `phase == PHASE_PRIMARY`:
   - If `device.isReceiveInProgress()`: defer; set `phase_end_ms = now + 1`;
     return. Primary wins.
   - `switchTo(SECONDARY, false)`; on success set phase secondary,
     `phase_end_ms = now + secondary_visit`.
8. If `phase == PHASE_SECONDARY`:
   - If `device.isReceiveInProgress()`:
     - active mode: on `switchTo(PRIMARY, true)` success (abort RX), call
       `noteAbort()`, set phase primary, `phase_end_ms = now + primary_visit`.
       On failure, keep phase secondary and retry.
     - idle mode: hold; set `phase_end_ms = now + RADIO2_HOLD_POLL_MS`; return.
   - Else on `switchTo(PRIMARY, false)` success, set phase primary,
     `phase_end_ms = now + primary_visit`.

`switchTo(profile, abort_receive, force = false)`:

```cpp
bool Radio2::switchTo(uint8_t profile, bool abort_receive, bool force = false) {
  if (profile == current && !force) return true;
  if (profile == RADIO_PROFILE_SECONDARY && !enabled) return false;
  // A complete packet is never abandoned: let core read it first.
  if (device.hasCompletedReceive()) return false;
  // A receive in progress is only abandoned when the caller explicitly asks.
  if (!abort_receive && device.isReceiveInProgress()) return false;
  const Radio2Profile& p = profile == RADIO_PROFILE_PRIMARY ? primary : secondary;
  if (!device.retune(p.freq, p.bw, p.sf, p.cr, abort_receive)) {
    noteSwitchFailure();
    return false;
  }
  current = profile;
  noteSwitch();
  return true;
}
```

A `false` return from `switchTo()` is either "busy" (a packet is pending or in
progress) or a real retune failure. Busy retries next loop. A real failure sets
`phase_end_ms = millis() + RADIO2_SWITCH_RETRY_MS`; after
`RADIO2_MAX_SWITCH_FAILURES`, disable scanning (stay primary) and report
`error=switch` in status. A config change re-enables attempts.

### 9.7 `getSleepMs()`

`MyMesh::getSleepMs()` returns `radio2.getSleepMs()`.

`Radio2::getSleepMs()`:

- 0 if disabled or paused.
- 1 if `!device.isInRecvMode()`, `hasCompletedReceive()`, or
  `isReceiveInProgress()` (wake soon; do not sleep through a packet).
- Otherwise `delta = phase_end_ms - now`; if `delta <= 0` return 1; else
  `min(delta, RADIO2_SLEEP_MAX_MS)`.

This is what lets `main.cpp` sleep between visits while the radio stays in RX.

### 9.8 TX interaction

- `selectTxProfile(profile)` is called by `Dispatcher::checkSend()` before TX.
- If `profile == current`, return true.
- If radio2 is off/paused and `profile == secondary`, fall back to primary and
  return true (count fallback).
- If `hasCompletedReceive()` or `isReceiveInProgress()`, return false; the
  dispatcher retries next loop.
- Otherwise `switchTo(profile, false)`; on success also set `phase` to match
  `profile` and `phase_end_ms = millis() + <that profile's visit>` so the
  scanner does not immediately undo the TX retune. Return true.
- TX is never aborted by the scheduler. `Radio2::loop()` sees
  `!isInRecvMode()` during TX and returns.
- After TX, the scanner resumes from the current profile; the next `loop()`
  computes the next visit. Do not try to “catch up” missed visits.

### 9.9 Primary activity

`MyMesh::onRecvPacket()` calls `radio2.notePrimaryPacket()` when
`rx_profile == RADIO_PROFILE_PRIMARY`. This updates
`last_primary_packet_ms` for every parsed primary packet, including packets the
filter or policy later drops.

A primary packet in progress at a secondary visit deadline defers the visit.
A primary packet that arrives during a secondary visit is not heard; the visit
bound ensures its preamble survives to the next primary visit.

### 9.10 Idle hold tradeoff

In idle mode, a secondary packet in progress at the visit deadline is allowed
to finish. This can extend primary blind time beyond `primary_bound_us`. It is
the only way to receive long secondary packets. The 30 s idle threshold makes
it rare. If a primary packet arrives during the hold, it can be missed. This is
the explicit tradeoff for “secondary should not drop when primary is idle.”

If strict primary protection is ever required, add a `radio2 strict` option
that disables the idle hold. Do not make it the default.

## 10. Persistence

### 10.1 File

`/radio2_cfg`, version 1, CRC-16 over the payload, staged save, `.bak` recovery.

### 10.2 Record

```cpp
#define RADIO2_CFG_FILE          "/radio2_cfg"
#define RADIO2_CFG_VERSION       1
#define RADIO2_CFG_MAGIC         "R2CF"

struct Radio2CfgRecord {
  char     magic[4];          // "R2CF"
  uint8_t  version;           // 1
  uint8_t  enabled;           // 0/1
  uint8_t  policy_primary;    // Radio2Action
  uint8_t  policy_secondary;  // Radio2Action
  uint8_t  advert;            // Radio2Advert
  uint8_t  sf;
  uint8_t  cr;
  float    freq_mhz;
  float    bw_khz;
};
static_assert(sizeof(Radio2CfgRecord) == 20,
              "Radio2CfgRecord payload is frozen at 20 B");
#define RADIO2_CFG_PAYLOAD_BYTES 20
#define RADIO2_CFG_RECORD_BYTES  22   // payload + 2 B CRC-16
```

Field order is deliberate: the byte fields come before the floats so there is
only one padding byte and the size is 20. Do not reorder without a version bump.

### 10.3 Validation

`radio2ValidateFile(File&, void*)`:

- read exactly `RADIO2_CFG_RECORD_BYTES`;
- magic == `R2CF`;
- version == 1;
- enabled <= 1;
- policy values <= 3;
- advert <= 1;
- sf 5..12, cr 5..8;
- freq/bw finite and in the accepted range;
- CRC matches.

`load()`:

- reset to defaults (off, same/same, advert primary, preset zero);
- `chooseConfigToLoad()`;
- if recovered from `.bak`, mark dirty for a repair save;
- if invalid, keep defaults.

`save()`:

- `saveStaged()` with write/validate callbacks;
- clear `LazySave` only on success; `retryLater()` on failure.

### 10.4 Defaults

```cpp
enabled = 0;
policy_primary = RADIO2_ACTION_SAME;
policy_secondary = RADIO2_ACTION_SAME;
advert = RADIO2_ADVERT_PRIMARY;
freq_mhz = 0; bw_khz = 0; sf = 0; cr = 0;
```

`set radio2 off` keeps the preset and policy; only `enabled` changes.

### 10.5 Future versions

Append new fields after `bw_khz` and bump `RADIO2_CFG_VERSION`; keep the v1
prefix byte-identical. Add migration in `load()`. Add a `static_assert` for the
new size.

### 11.1 Dispatch

```cpp

         (command[6] == 0 || command[6] == ' ')) {

```

The command is the bare `radio2` verb, matching `filter`/`battery`/`fleet`.
There is deliberately no `get radio2` / `set radio2` alias: one parser, one

### 11.2 Commands

```text
radio2

radio2 timing
```

- `radio2 policy X` sets both origins to X.

- `radio2 advert` with no args = current advert policy.

### 11.3 Replies

Set:

```text

OK - radio2 off
OK - radio2 policy primary=same,secondary=other
OK - radio2 advert both
```

Value readouts use the same bare form as the other fork CLIs.

Policy (`radio2 policy`):

```text
primary=same,secondary=same
```

Advert (`radio2 advert`):

```text
primary
```

Status (`radio2` or `radio2 status`, one line, bounded by `CLI_REPLY_MAX`):

```text
on; at=radio2; mode=idle; split=38/62; nf=-117; sw=12; swf=0; rx=4/9; tx=1/6; both=0; bdrop=0; drop=0; abrt=0
```

`mode=active; lossy` marks an active-mode primary visit long enough that a

```text
off
```

```text
off; conflict=radio.rxps
```

```text
on; apply=pending; at=primary
```

```text
primary=49ms; secondary=82ms; split=38/62; switch=3ms; mode=idle
```

If unusable:

```text
unusable: secondary capture 49ms > primary-safe 20ms
```

### 11.4 Errors

Keep replies short and actionable:

```text
Err - usage: radio2 | radio2 status | radio2 timing | radio2 <freq>,<bw>,<sf>,<cr> | radio2 off | radio2 policy [<primary> [<secondary>]] | radio2 advert primary|both
Err - radio2 preset must be <freq>,<bw>,<sf>,<cr>
Err - radio2 policy must be same|other|both|drop
Err - radio2 advert must be primary|both
Err - radio2 overlaps radio
Err - radio2 preset cannot be scanned without degrading radio
Err - radio.rxps is on; set radio.rxps off first
Err - radio2 is on; set radio2 off first
Err - radio2 conflicts with extra.sf; clear extra SF first
Err - tempradio active; wait for it to revert
```

The usage line may exceed 157 bytes; if so, shorten it or split the command
surface into a short usage plus `radio2 status` details. Never write past
`CLI_REPLY_MAX`.

### 11.5 Parsing

Use `CliUtil.h`:

- `cliPrepare()` for quote balance and command length;
- `nextToken()` for subcommands;
- `mesh::Utils::parseTextParts()` for the comma tuple;
- `parseIntRange()` for SF/CR;
- `strtof()` with an end pointer for freq/bw, rejecting trailing bytes and
  non-finite values.

Validation ranges match `set radio`:

- freq 150..2500 MHz
- bw 7..500 kHz
- sf 5..12
- cr 5..8

Reject a preset that overlaps the primary:

```text
abs(freq2 - freq1) < (bw1 + bw2) / 2 + RADIO2_OVERLAP_GUARD_KHZ
```

Reject if the timing validation in §9.3 fails.

### 11.6 Deferred apply

`set radio2` / `radio2 off` persist immediately but defer the RF change:

- set `pending_apply = true`, `pending_apply_at_ms = millis() + RADIO2_APPLY_DELAY_MS`;
- `Radio2::loop(fs, quiet)` applies when `quiet` is true and the deadline has
  passed;
- `quiet` is `_mgr->getOutboundTotal() == 0` from `MyMesh::loop()`;
- this lets a remote admin on the secondary profile receive the command reply
  on the old secondary config before the radio changes.

`radio2 policy` and `radio2 advert` do not change RF; apply immediately.

### 12.8 Adverts

Modify `MyMesh::sendSelfAdvertisement()`:

- create the advert packet as today;
- send it on primary (default target 0);
- if `radio2.advertBoth()`, create a copy with `obtainNewPacket()`, copy the
  packet, set target secondary, and send it with the same flood/zero-hop path.

For flood:

```cpp
mesh::Packet* pkt = createSelfAdvert();
if (pkt) {
  sendFloodScoped(default_scope, pkt, delay_millis, _prefs.path_hash_mode + 1);
  if (radio2.advertBoth()) {
    mesh::Packet* copy = obtainNewPacket();
    if (copy) {
      *copy = *pkt;   // pkt has already been sent/released? See note.
      copy->setTxProfile(RADIO_PROFILE_SECONDARY);
      sendFloodScoped(default_scope, copy, delay_millis, _prefs.path_hash_mode + 1);
    }
  }
}
```

Important: `sendFloodScoped()` queues the packet; it does not release it
immediately. The packet is still valid until the dispatcher sends it. Copy
before or after queueing is fine as long as the pointer is valid. To avoid
aliasing, create the copy **before** sending the first packet:

```cpp
mesh::Packet* pkt = createSelfAdvert();
if (!pkt) return;
mesh::Packet* copy = nullptr;
if (radio2.advertBoth()) {
  copy = obtainNewPacket();
  if (copy) *copy = *pkt;
}
sendFloodScoped(default_scope, pkt, delay_millis, ...);
if (copy) {
  copy->setTxProfile(RADIO_PROFILE_SECONDARY);
  sendFloodScoped(default_scope, copy, delay_millis, ...);
}
```

For zero-hop, use `sendZeroHop()` similarly.

`sendNodeDiscoverReq()` is a control request, not an advert; leave primary.

## 13. Conflicts and capabilities

### 13.1 RXPS

- radio2 refuses to start if `_prefs.rxps.enabled`.
- `set radio2` refuses if RXPS enabled.
- `set radio.rxps on/...` refuses if radio2 enabled.
- `set radio.rxps off` allowed.
- If both persisted, radio2 off; primary RXPS runs; status reports conflict.

### 13.2 `extra.sf` side detectors

If `_prefs.extra_sf[0] != 0`, radio2 refuses to start and `set radio2` refuses.
Side detectors are primary-only in v1. Clear them with the core command before
enabling radio2.

### 13.3 `tempradio`

Pause radio2 while a temporary primary is active. Revalidate on revert.

### 13.4 `set radio` (primary)

`set radio` only takes effect on reboot. At boot, validate the secondary
against the new primary. If it overlaps or is unscannable, radio2 stays off and
reports the reason. Do not modify the primary to accommodate radio2.

### 13.5 `cad` / `int.thresh`

`cad` works because `selectTxProfile()` runs before `checkSend()`'s channel
check. `int.thresh` uses the shared noise floor; it may be approximate while
scanning. No per-profile floor in v1.

### 13.6 `powersaving`

Allowed and required. `getSleepMs()` provides the deadline. If `powersaving`
is off, radio2 polls; higher power, still correct.

### 13.7 Bridge / MQTT observer

No special handling. The observer captures both profiles; `Packet::getRxProfile()`
is available if a future schema wants it. Bridge traffic is local; primary
unless a future policy says otherwise.

### 13.8 Battery / fleet

Battery gate and fleet hooks are unchanged. Policy `drop` is evaluated before
the battery/filter gates; fleet `onGroupData` still runs. Fleet replies use the
captured origin profile.

## 14. Filter phase 2 (not v1)

v1: filters apply to both profiles equally.

Phase 2: add a per-rule origin predicate.

- `FilterRule` has a reserved byte at offset 187, format-guaranteed zero in v7.
- Bump `FILTER_CFG_VERSION` to 8 and use that byte as `radio_mask`:
  - bit 0 = primary
  - bit 1 = secondary
  - 0 = any (default)
- v7 migration sets `radio_mask = 0`.
- `checkPacket()` and `checkContent()` already receive the `Packet*`; read
  `pkt->getRxProfile()` and match the mask. No signature change.
- CLI: `filter add radio=any|primary|secondary ...`; `filter get` renders it.
- Default rules (no `radio=`) apply to both.
- A filter rule cannot override the capability rules: direct/ACK/unicast flood
  DMs still cannot cross.
- Add tests for v7→v8 migration, roundtrip, CLI, and matching.

Do not fold this into v1; it is a persisted-layout change and needs its own
migration/tests.

## 19. Risks and open items

1. **nRF52 timed wake** is the highest-risk piece. Validate on hardware; keep a
   correct fallback if the timer cannot be armed.
2. **Retune time** varies by radio family/board. Measure; the 3 ms default is
   conservative. A boot self-test is optional.
3. **Idle hold** can miss a primary packet after a long primary silence. This is
   the explicit tradeoff for long secondary packets. A future `radio2 strict`
   can disable it.
4. **Cross-profile broadcast flood** can create duplicate traffic if multiple
   bridges use `both`. Dedup/hop limits bound loops; recommend one-way `other`
   or a single bridge.
5. **STM32 flash** is already exhausted on `wio-e5_repeater` in the upstream
   tree: the baseline overflows `FLASH` by 184 bytes before this feature is
   added. Per the repo rule, an upstream-failing target is not patched as part
   of a fork change; the release ships without that asset. The other required
   filesystem families (`Xiao_S3_WIO_repeater`, `RAK_4631_repeater`,
   `PicoW_repeater`) compile with radio2. If that target's flash is ever fixed,
   radio2 fits the same way it does on the others — no build flag is compiled
   in today.
6. **Upstream sync** now touches `Packet`, `Dispatcher`, `StaticPool`,
   `RadioLibWrappers`, `MainBoard`, and board files. Keep the edits generic and
   behaviour-neutral; add a merge-playbook row only with approval.
7. **No per-profile noise floor** means `int.thresh` is approximate while
   scanning. Accepted; status shows the shared value.
8. **Filter phase 2** is a separate persisted-layout change; do not mix it into
   the radio2 core change.

## 20. Acceptance criteria

The feature is done when:

- radio2 can be enabled with its own preset and config file;
- primary remains the default and is protected under traffic;
- secondary gets the maximum safe share when primary is idle;
- powersaving works with radio2 on nRF52 and ESP32;
- RXPS and radio2 cannot both be enabled;
- policy `same/other/both/drop` works per origin;
- only broadcast flood crosses profiles;
- direct/ACK/unicast flood DMs stay on origin;
- replies go to the origin profile;
- adverts can be primary-only or both;
- filters apply to both profiles equally;
- all existing native suites pass unchanged;
- `native_radio2` and sanitizer suites pass;
- the four required firmware targets compile;
- on-air tests confirm the policy and powersaving behaviour;
- `RADIO2.md` documents the user-facing commands and the tradeoffs.
